# Plan: User Profile Page Implementation (/settings/account)

## Context
The user profile page is referenced in `nav-user.tsx` but doesn't exist. The current system has:
- Auth store with token, roles, permissions, tenant info
- User service for admin CRUD operations
- Employee ↔ User linking (one-to-one)
- File upload infrastructure (`/api/v1/files/upload` and `/api/v1/media/upload`)
- Avatar UI component (Radix UI based)
- Hardcoded user data in NavUser and sidebar

**Missing:**
- `/api/v1/auth/me` endpoint
- `/api/v1/auth/update-profile` endpoint
- `/api/v1/auth/change-password` endpoint
- MFA endpoints (TOTP setup, verify, backup codes)
- Settings account page
- User avatar field in ApplicationUser
- Current user's employee link lookup

## Goals
Implement `/settings/account` with full profile management:
1. View/update personal info (name, email)
2. Change password
3. Upload/manage avatar
4. MFA TOTP setup with QR code and backup codes
5. View and manage linked employee
6. Language/locale preferences

## Architecture Decisions

### 1. API Endpoints (AuthController extension)
| Method | Route | Purpose |
|--------|-------|---------|
| GET | `/api/v1/auth/me` | Get current user profile with employee link |
| PUT | `/api/v1/auth/me` | Update current user profile (name, email, locale) |
| POST | `/api/v1/auth/change-password` | Change password |
| GET | `/api/v1/auth/me/mfa` | Get MFA status |
| POST | `/api/v1/auth/me/mfa/setup` | Initiate MFA setup (returns QR code + secret) |
| POST | `/api/v1/auth/me/mfa/verify` | Verify TOTP code, enable MFA |
| POST | `/api/v1/auth/me/mfa/disable` | Disable MFA |
| GET | `/api/v1/auth/me/mfa/backup-codes` | Get/regenerate backup codes |

### 2. Data Model Extensions
**ApplicationUser** (Domain/Security):
- Add `AvatarUrl` (string, nullable)
- Add `PreferredLocale` (string, default "es")
- Existing: `TwoFactorEnabled` (Identity), `PhoneNumber` (Identity)

**Employee** already has `PreferredLocale` and `UserId` link

### 3. Permission Requirements
- `users:read` - View own profile (self)
- `users:manage` - NOT required for self-update (separate logic)
- `mfa:configure` - Required for MFA setup/change
- New: `profile:update` - For self profile updates (or use users:manage with ownership check)

### 4. Avatar Upload
- Use existing `/api/v1/media/upload` (requires `tenant:write`)
- Or create lightweight `/api/v1/auth/me/avatar` for avatar-specific upload
- Store URL in `ApplicationUser.AvatarUrl`

### 5. Employee Link Management
- Add reverse lookup: GET `/api/v1/employees/linked-to-user/{userId}` or include in `/me`
- Profile shows linked employee name, role, allows unlinking (if user has `employees:manage`)

## Implementation Plan

### Phase 1: Backend - Core Profile Endpoints

#### 1.1 Extend ApplicationUser
```csharp
// AssetHub.Domain.Security.ApplicationUser
public string AvatarUrl { get; set; } = string.Empty;
public string PreferredLocale { get; set; } = "es";
```

#### 1.2 Create Me Queries/Commands
- `GetCurrentUserQuery` → returns `CurrentUserDto` (includes employee link if exists)
- `UpdateCurrentUserCommand` (name, email, preferredLocale)
- `ChangePasswordCommand` (currentPassword, newPassword)
- `UploadAvatarCommand` (uses existing media upload, updates AvatarUrl)

#### 1.3 Create MFA Commands/Queries
- `GetMfaStatusQuery` → { isEnabled, recoveryCodesRemaining }
- `InitiateMfaSetupCommand` → { secret, qrCodeUri, backupCodes }
- `VerifyMfaSetupCommand` (totpCode) → enables MFA
- `DisableMfaCommand` (password) → disables MFA
- `RegenerateBackupCodesCommand` → { backupCodes }

#### 1.4 Add AuthController Endpoints
All endpoints under `[Authorize]` with proper validation.

## Risks & Mitigation

| Risk | Mitigation |
|------|------------|
| Email uniqueness on update | Check tenant-scoped uniqueness in command handler |
| MFA lockout | Backup codes, admin can disable via user management |
| Avatar URL stale | Invalidate on update, use cache-busting |
| Employee unlink permissions | Only users with `employees:manage` can unlink |
