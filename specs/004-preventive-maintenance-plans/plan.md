# Implementation Plan: Preventive Maintenance Plans

**Branch**: `004-preventive-maintenance-plans` | **Date**: 2026-08-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-preventive-maintenance-plans/spec.md`

**Note**: This plan covers a full recurring preventive-maintenance feature for AssetHub. The existing codebase already contains a `PreventivePlan` entity and an `EvaluatePreventivePlansCommand`, but they are incomplete: the entity lives in the wrong domain namespace, plan execution only supports single-asset targets, and there is no UI, execution log, notification, or scheduling endpoint.

## Summary

Extend AssetHub so maintenance managers can create recurring preventive plans attached to a single asset or to all assets of a template. Each plan defines a cron schedule, the type of work item(s) to generate (work task, maintenance order, or both), relative due dates, asset-state conditions, and default assignment. An externally invoked evaluation endpoint processes all due plans, creates the configured work items, records every execution, and sends in-app notifications. The frontend gets a preventive-plans list, creation/edit form, execution log, calendar view, and an asset-detail widget.

## Technical Context

- **Language/Version**: .NET 10 (backend), TypeScript/React (frontend)
- **Primary Dependencies**: ASP.NET Core, MediatR, Entity Framework Core, Cronos (cron parsing), React Query, Tailwind CSS
- **Storage**: SQL Server (tenant databases via Aspire)
- **Testing**: xUnit + WebApplicationFactory for backend integration tests; no established frontend test framework in the repo
- **Target Platform**: Web application (desktop browser, responsive where practical)
- **Project Type**: Full-stack web application with separated backend/frontend
- **Performance Goals**: Evaluation endpoint should process at least 1,000 plan occurrences per minute; calendar/previews return next 12 occurrences in under 2 seconds
- **Constraints**: Multi-tenant; scheduler must be invoked by external cron; generated work items must be idempotent across repeated endpoint calls
- **Scale/Scope**: Company-wide asset management; expected thousands of assets and hundreds of active plans per tenant

## Complexity Tracking

No constitution violations required. The following decisions are the main sources of complexity:

| Decision | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Separate `WorkTask` and `MaintenanceOrder` generation | Spec requires generating tasks, orders, or both | Generating only tasks would not cover formal maintenance workflows |
| Execution log table | Spec requires complete audit trail of every run | Relying on existing lifecycle events lacks plan-specific context |
| Idempotency by (Plan, Asset, Occurrence) | External cron may invoke endpoint multiple times | Without idempotency, duplicate work items would be created |
| Condition evaluation per asset state | Users want to skip obsolete/decommissioned assets | Always generating items for every asset would create noise |

## Research Decisions

See [research.md](./research.md) for detailed rationale.

Key decisions:

1. **Cron handling**: Continue using the `Cronos` library already referenced by the project.
2. **Scheduler trigger**: Expose a single `POST /api/preventive-plans/evaluate-all` endpoint; no background service in the initial release because the spec explicitly chose an external cron.
3. **Idempotency**: Execution log keyed by `PreventivePlanId + AssetId + Occurrence` (the scheduled `NextRunAt` value) prevents duplicates.
4. **Missed occurrences**: Process the current `NextRunAt` and advance it; repeated endpoint calls catch up naturally. This avoids a complex catch-up policy for the first release.
5. **Notifications**: Add a per-tenant `Notification` table populated by an event handler reacting to successful work-item generation.
6. **Assignment**: Plans store optional default employee/team. `WorkTask` uses both; `MaintenanceOrder` only has an `AssignedEmployeeId`, so team-only defaults leave it unassigned and log a note.
