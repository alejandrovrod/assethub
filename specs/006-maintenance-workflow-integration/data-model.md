# Data Model: Maintenance Workflow Integration

## New / Changed Entities

### Asset

Represents the physical or logical item under maintenance.

**Added navigation properties**:

| Property | Type | Description |
|---|---|---|
| `Incidents` | `ICollection<Incident>` | All incidents reported against this asset. |
| `MaintenanceOrders` | `ICollection<MaintenanceOrder>` | All maintenance orders for this asset. |
| `WorkTasks` | `ICollection<WorkTask>` | All work tasks linked directly to this asset. |
| `PreventivePlans` | `ICollection<PreventivePlan>` | Plans targeting this asset directly. |

The asset lifecycle (`State`) remains defined by `AssetTemplate.LifecycleStates`.

### Incident

Represents a reported problem.

**Added navigation properties**:

| Property | Type | Description |
|---|---|---|
| `MaintenanceOrders` | `ICollection<MaintenanceOrder>` | Corrective or linked orders created from this incident. |
| `WorkTasks` | `ICollection<WorkTask>` | Tasks derived directly from this incident. |

**State constants** (`IncidentStates`):

- `reported`, `triaged`, `assigned`, `in_progress`, `resolved`, `closed`, `cancelled`
- Terminal states: `closed`, `cancelled`
- Active states: `reported`, `triaged`, `assigned`, `in_progress`

`resolved` is now an intermediate state; the incident can still move to `closed` after the linked corrective order is verified.

### MaintenanceOrder

Represents a formal maintenance job.

**Added navigation property**:

| Property | Type | Description |
|---|---|---|
| `WorkTasks` | `ICollection<WorkTask>` | Child tasks belonging to this order. |

**State constants** (`MaintenanceOrderStates`):

- `draft`, `approved`, `scheduled`, `in_progress`, `done`, `verified`, `cancelled`
- Active states: `draft`, `approved`, `scheduled`, `in_progress`
- Terminal states: `verified`, `cancelled`

**Kind constants** (`MaintenanceOrderKinds`):

- `corrective`, `preventive`

### PreventivePlan

Represents a recurring schedule that generates work items.

**Added navigation properties**:

| Property | Type | Description |
|---|---|---|
| `WorkTasks` | `ICollection<WorkTask>` | Tasks generated by this plan. |
| `MaintenanceOrders` | `ICollection<MaintenanceOrder>` | Orders generated by this plan. |

### WorkTask

Represents a unit of work.

**State constants** (`WorkTaskStates`):

- `todo`, `in_progress`, `done`, `cancelled`
- Terminal states: `done`, `cancelled`

**Validation rule**: A task can reference at most **one** of `AssetId`, `IncidentId`, `MaintenanceOrderId`, `PreventivePlanId`, `TaskRecurrenceId`. `IsIndependent` must be `true` when no parent is set.

## Relationships

```text
Asset 1--* Incident
Asset 1--* MaintenanceOrder
Asset 1--* WorkTask
Asset 1--* PreventivePlan

Incident 1--* MaintenanceOrder
Incident 1--* WorkTask

MaintenanceOrder 1--* WorkTask
MaintenanceOrder *--0..1 PreventivePlan

PreventivePlan 1--* WorkTask
PreventivePlan 1--* MaintenanceOrder
```

## EF Core Configuration Changes

- `Incident`:
  - Explicit FK to `CatalogItem` for `TypeId`.
  - Explicit FK to `CatalogItem` for `PriorityId`.
- `PreventivePlan`:
  - Explicit FK to `Employee` for `DefaultAssignedEmployeeId`.
  - Explicit FK to `Team` for `DefaultAssignedTeamId`.
- All inverse navigation properties are configured with `OnDelete(DeleteBehavior.Restrict)` to prevent cascade deletes.

Migration `20260818202613_LinkMaintenanceWorkflows` adds the missing foreign keys and redeclares existing relationships to use the new inverse navigations.
